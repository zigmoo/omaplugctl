OmaPlugCtl

Click the US electrical plug in the bar to open a scrollable list of bar plugins. Every row shows the plugin icon, name, and saved position or disabled state. An Omarchy-style update icon appears only when upstream changes are available; up-to-date rows have no update icon. Unchecked sources, missing repositories, failed checks, and local changes are identified explicitly. Hover the icon, name, or position text for a description of the plugin's function after a short delay. Descriptions come from the local plugin catalog, with widget-specific details when provided; no network lookup is needed. Long descriptions wrap, and plugin-supplied text is rendered as plain text. Plugins without descriptions say so explicitly. Inline icons provide Enable/Disable, About, and More, with their own action tooltips. More expands instance-specific Move controls and, for installed third-party plugins, Uninstall. Uninstall always requires explicit confirmation. Built-ins cannot be removed. OmaPlugCtl appears in its own list so it can be updated when its Git origin is configured; it cannot disable or remove itself.

The pinned **Bar position** control is a compact 96×54 screen diagram. An accent-colored strip marks the current edge, and the other three edges remain faintly visible before hover. Click another screen edge to move the bar there; hover highlights the click target, with a tooltip naming the edge. The diagram uses geometry instead of visible direction labels and supports Tab and Enter/Space. The controls use `omarchy bar position` and confirm the saved position before selecting the new edge; a failed change leaves the last confirmed selection and shows an error. The menu stays open and follows the bar to its new edge, including switches between horizontal and vertical bars. Its plugin list and scroll position are preserved.

The panel follows the bar font and Omarchy theme. Header counts, bar-position controls, and operation status remain visible while scrolling. Tab focuses buttons; Enter/Space activates them; Up/Down scroll the focused plugin list; Escape closes. Refresh reads the current registry, layout, and bar position. Mutations render final state only after datasource readback. About resolves local source metadata before using the public catalog.

Each description tooltip ends with a smaller footer: **Local update YYYY-MM-DD · Author · Default Omarchy**. The last note identifies a default Omarchy plugin and appears only for first-party plugins, never personal clones. Dates are the newest modification date among that installed plugin's files, excluding Git data, caches, build output, and archives; single-file built-ins use only their own manifest and declared entry points. They describe the installed files, not an upstream release. Authors come from the installed manifest. Missing authors and dates are explicitly marked as unavailable rather than inferred.

**Check updates** explicitly contacts the installed plugins' source repositories. Normal refreshes use cached results and perform no network check; a cached up-to-date result expires after one day. Each repository is fetched once per check, even when it supplies several built-in plugins. The check never installs code or changes the working tree. Built-in plugin availability is scoped to that plugin's files in the Omarchy repository.

Hover an update icon to see the latest pending change date and up to three commit summaries from the fetched source. This needs no click or extra network request and renders repository text as plain text. Click the icon to open the supported Omarchy plugin updater in a terminal to review its diff and confirm installation. No update is automatically confirmed. Built-ins explicitly identify the broader Omarchy system update before opening the standard updater. Local modifications and diverged history keep their indicator and notes but block installation with an explanation; local changes are not discarded. Plugins copied without Git metadata say **No update repository**; packaged built-ins without source checkouts say **Updated with Omarchy** and offer the system updater under More. The manager is reopened after the plugin updater's shell rescan.

**Sort by** supports **Name**, **Screen order**, and **Pending update date**. Screen order follows the bar's sections and widget slots, with disabled plugins last. Pending updates sort newest first; other plugins follow alphabetically. The choice is saved in OmaPlugCtl's own bar settings and survives restarts. A plugin appearing more than once uses its first screen position for sorting.

Source repository: ~/dil/plugins/omaplugctl, with DIL's `master` trunk. Installed link: ~/.config/omarchy/plugins/moo.omaplugctl. The source is separate from Omarchy, and the original update-blocking source patch and reapplication hook remain retired. The archive subdirectory preserves the original partial source patch and the prior dropdown UX. For self-updates, configure this repository's `origin`; the same supported updater then works through the active symlink.

Open from CLI: omarchy-shell moo.omaplugctl show
Close: omarchy-shell moo.omaplugctl hide
Inspect menu state: omarchy-shell moo.omaplugctl status
Move through the menu controller: omarchy-shell moo.omaplugctl position top
Backend checks: cd ~/dil/plugins/omaplugctl && python3 -m unittest -v
Check sources from CLI: python3 ~/dil/plugins/omaplugctl/controller.py check-updates

The lightweight Widget.qml only owns the bar icon. Service.qml owns the persistent menu, operation process, list, and scroll state. Rebuilt icons register their new anchor with that service, so changing bar orientation cannot destroy the open menu or cancel its operation.

The exact Ctrl+right-click-on-another-widget interaction still needs an upstream host extension. The manager works with the existing supported plugin and CLI APIs; no such source extension is installed.
