OmaPlugCtl

Click the US electrical plug in the bar to open a scrollable list of bar plugins. Every row shows the plugin icon, name, and saved position or disabled state. An Omarchy-style update icon appears only when upstream changes are available; up-to-date rows have no update icon. Unchecked sources, missing repositories, failed checks, and local changes are identified explicitly. Hover the icon, name, or position text for a description of the plugin's function after a short delay. Descriptions come from the local plugin catalog, with widget-specific details when provided; no network lookup is needed. Long descriptions wrap, and plugin-supplied text is rendered as plain text. Plugins without descriptions say so explicitly. Inline icons provide Enable/Disable, About, and More, with their own action tooltips. More expands instance-specific Move controls and, for installed third-party plugins, Uninstall. Uninstall always requires explicit confirmation. Built-ins cannot be removed. OmaPlugCtl appears in its own list so it can be updated when its Git origin is configured; it cannot disable or remove itself.

The pinned **Bar position** control is a compact 96×54 screen diagram. An accent-colored strip marks the current edge, and the other three edges remain faintly visible before hover. Click another screen edge to move the bar there; hover highlights the click target, with a tooltip naming the edge. The diagram uses geometry instead of visible direction labels and supports Tab and Enter/Space. The controls use `omarchy bar position` and confirm the saved position before selecting the new edge; a failed change leaves the last confirmed selection and shows an error. The menu stays open and follows the bar to its new edge, including switches between horizontal and vertical bars. Its plugin list and scroll position are preserved.

The panel follows the bar font and Omarchy theme. Header counts, bar-position controls, and operation status remain visible while scrolling. Tab focuses buttons; Enter/Space activates them; Up/Down scroll the focused plugin list; Escape closes. Refresh reads the current registry, layout, and bar position. Mutations render final state only after datasource readback. About resolves local source metadata before using the public catalog.

Each description tooltip ends with a smaller footer: **Local update YYYY-MM-DD · Author · Default Omarchy**. The last note identifies a default Omarchy plugin and appears only for first-party plugins, never personal clones. Dates are the newest modification date among that installed plugin's files, excluding Git data, caches, build output, and archives; single-file built-ins use only their own manifest and declared entry points. They describe the installed files, not an upstream release. Authors come from the installed manifest. Missing authors and dates are explicitly marked as unavailable rather than inferred.

**Check updates** explicitly contacts the installed plugins' source repositories. Normal refreshes use cached results and perform no network check; a cached up-to-date result expires after one day. Each repository is fetched once per check, even when it supplies several built-in plugins. The check never installs code or changes the working tree. Built-in plugin availability is scoped to that plugin's files in the Omarchy repository.

Hover an update icon to see the latest pending change date and up to three commit summaries from the fetched source. This needs no click or extra network request and renders repository text as plain text. Clicking authorizes the configured **agent review** and publication to the source GitHub repository. The worker runs in the background with no terminal or prompts; the menu shows progress, and the completed GitHub outcome opens automatically. The full diff is pinned to the installed and fetched upstream commits, with built-in reviews scoped to that plugin. Requests and reports include the authoritative origin repository URL, immutable commit links and an exact tree-comparison link for supported hosts (GitHub and GitLab). Agents must cite upstream file/line permalinks rather than chunk-line coordinates. Git credentials and query tokens never enter report links; unknown hosts retain their repository link without guessed commit routes, and local origins are identified as having no browser URL. Large updates are automatically divided at file/hunk boundaries into bounded requests; even oversized individual lines are covered without dropping bytes. A coverage manifest records the complete snapshot hash and byte ranges. All parts must return findings before a consolidated report is delivered; the full report retains original part findings. Binary payloads are explicitly outside textual diff coverage. Completed parts remain recorded if a later request fails. Duplicate clicks cannot run concurrent reviews of the same plugin. The full findings are posted as a comment on the exact reviewed GitHub commit using an authenticated `gh` CLI. Reports over the comment limit are split without losing text and linked from the first comment. Server readback confirms the author, commit, body and outcome URL before reporting success. Publication retries reuse saved findings and recover an ambiguous POST timeout without duplicate comments. **Retry GitHub publication** is available after upload failures; it does not run the reviewer again. GitHub authentication or repository restrictions appear as a publication error while the local/DIL report remains available. Sources outside GitHub retain their DIL/local outcome and explicitly say the source is not on GitHub.

**Plugins** contains the existing placement controls, sorting and list. **Config** offers **Agent selection source: DIL / Omarchy**, then agent/harness and model selectors. DIL is the default source for DIL users; others default to Omarchy. Source and native selection are saved in this plugin's Omarchy bar settings (`reviewerSource`, `nativeReviewer`), independently of Omarchy's global agent preference. The current reviewer changes only after a settings write and readback. Selecting a draft model does not start a review.

The DIL source reads the machine override `settings_tool get defaultPreferredReviewer.<hostname>`, falling back to `defaultPreferredReviewer`. Its value is an **agent dispatch binding ID**, resolved through `agent_dispatch_binding_registry_tool` and active `harness_registry_tool` entries. The binding owns the agent, harness, model, and reasoning level. Config lists enabled bindings with available harness binaries and saves the machine override through `settings_tool`. Missing or disabled choices never silently select another reviewer.

The Omarchy source discovers the agent catalogue/default through `omarchy commands --json` and `omarchy default agent`, then reads models from each supported CLI: Codex's model cache, Cursor's `--list-models`, OpenCode's `models`, and Claude's configured model. Explicit provider homes and Omarchy subscription-account homes are respected. A configured-default-model choice remains available when the CLI has no model-list interface; model names are not invented. Current headless review adapters support Codex, Cursor, OpenCode, and Claude. Native choices run through their own CLIs and can be used without DIL. Model discovery runs when loading Omarchy Config; review clicks reuse that inventory. Authentication and provider/model access remain owned by each CLI.

Whenever DIL is present, reviews from either source create a personal Omarchy task, assign it to the selected agent, start it, and provide a canonical handoff. Each dispatched agent must pick up the task and record actual work, findings, limits and a verifiable per-request receipt through `task_tool`. The caller verifies that receipt, records durable part/final compositions, and supplies Revelator links. DIL-sourced dispatch uses `agent_tool review`; explicitly selected Omarchy dispatch uses the native CLI with deterministic harness identity and DIL task tracking. Harness permissions follow the selected runtime, while instructions permit DIL evidence writes and prohibit editing/executing plugin code or installing updates. Tasks stay in progress for operator disposition. Without DIL, the same complete review produces a report under XDG state. **View review on GitHub** in the plugin row opens the published outcome, with the existing DIL/local report as a fallback when publication is unavailable. Local status polling keeps progress and the completed report available without closing the menu. DIL continues to receive the task, work receipts, findings and published GitHub URL; it is optional for GitHub publication.

Review findings are advisory and are not independently verified bug confirmations. The background workflow ends with delivery of the report; it never opens an updater, prompts for input, or installs code. To install after considering the review, use Omarchy's separate supported plugin/system updater and its confirmation flow. Local modifications and diverged history remain intact. Binary payloads are outside the textual review. Plugins copied without Git metadata say **No update repository**; packaged built-ins without Git source checkouts cannot receive a source review. CLI publication retry: `python3 controller.py retry-publication <plugin-id>` (detached); review-only worker: `python3 controller.py review-update <plugin-id>` (no prompts).

**Sort by** supports **Name**, **Screen order** (the default), and **Pending update date**. Screen order follows the bar's sections and widget slots, with disabled plugins last. Pending updates sort newest first; other plugins follow alphabetically. The choice is saved in OmaPlugCtl's own bar settings and survives restarts. A plugin appearing more than once uses its first screen position for sorting.

Source repository: [zigmoo/omaplugctl](https://github.com/zigmoo/omaplugctl), with DIL's `master` trunk. Local development checkout: ~/dil/plugins/omaplugctl. Installed link: ~/.config/omarchy/plugins/moo.omaplugctl. The source is separate from Omarchy, and the original update-blocking source patch and reapplication hook remain retired. The archive subdirectory preserves the original partial source patch and the prior dropdown UX. GitHub is `origin`; the secondary development remote is `workshop`. Self-update reviews use the GitHub origin through the active symlink.

Open from CLI: omarchy-shell moo.omaplugctl show
Close: omarchy-shell moo.omaplugctl hide
Inspect menu state: omarchy-shell moo.omaplugctl status
Move through the menu controller: omarchy-shell moo.omaplugctl position top
Backend checks: cd ~/dil/plugins/omaplugctl && python3 -m unittest -v
Check sources from CLI: python3 ~/dil/plugins/omaplugctl/controller.py check-updates

The lightweight Widget.qml only owns the bar icon. Service.qml owns the persistent menu, operation process, list, and scroll state. Rebuilt icons register their new anchor with that service, so changing bar orientation cannot destroy the open menu or cancel its operation.

The exact Ctrl+right-click-on-another-widget interaction still needs an upstream host extension. The manager works with the existing supported plugin and CLI APIs; no such source extension is installed.
